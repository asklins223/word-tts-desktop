# 小猪 wordTTS：音频生成与系统录入整合方案

> 方案版本：v0.6（开发前收口版）<br>
> 最后复核：2026-09-03<br>
> 当前范围：试卷与课文外部系统录入；词汇完成统一结构预留，暂不执行外部录入。<br>
> 课文录入：2026-09-05 起接入（页面适配器 `platform_input.textbook`），配置字段为平台“新增课文”分类信息九项，解析器同步保留条目级中文译文。

## 1. 文档说明

本文档是当前确认版产品与交互方案，用于指导后续设计和开发。

本方案只描述产品流程、界面行为、字段来源、自动识别和模板复用，不包含具体代码实现。

核心目标：在不破坏现有音频生成流程的基础上，让用户可以选择“只生成音频”或“生成音频并录入系统”，并尽可能根据文档和历史应用配置模板自动补全系统录入配置。

无论用户选择试卷、课文还是词汇，解析结果都必须允许一个源文档包含多个录入单元，并让内容核对、音频产物和后续系统录入始终沿用同一套单元映射。

### 1.1 核心名词和唯一业务对象

`录入单元`是本方案唯一的业务分组概念：它表示一次需要独立准备参数、独立提交外部平台并独立记录结果的对象。试卷场景中的“一套试卷”和课文/词汇场景中的“一个单元”，在数据模型中都是同一个`录入单元`，不维护两套数量或状态。

- `unit_id`：应用内部稳定标识，一个录入单元对应一个 ID
- `录入 ID（entry_id）`：面向用户和后续脚本的录入记录 ID；用户开启系统录入后，单套文档生成 1 个，多套文档按每个录入单元各生成 1 个；同一任务内重试外部录入时保持不变。纯音频任务在用户点击`继续录入系统`前不强行创建外部录入记录
- `文档名称（document_name）`：当前录入平台中实际提交的、可用于搜索记录的试卷/课文名称（试卷取 `paperName`，课文取 `textbookNameZh`）；源文档文件名仍由工作区的 `source_filename` 保留，多套录入分别保留各自的平台名称
- `审阅文档名`：当前平台不提供稳定的单元审阅链接，因此结果页展示并支持复制提交到平台的文档名称；数据库仍保留 `review_url` 兼容字段，当前适配器明确置为不可用而不是失败
- `external_record_id`：外部平台返回的记录 ID，与应用自己的`entry_id`分开保存，不能互相替代

“第几套”只作为试卷界面的显示说法，“第几个录入单元”是课文/词汇界面的显示说法；底层统一使用`unit_id + entry_id`。如果用户因为音频质量问题新建任务，新的任务生成新的录入 ID，旧任务和旧录入 ID继续保留历史记录。

系统录入开启后，每个录入单元最终都要能展示以下三项核心信息：

```text
录入 ID：IN-xxxxxxxx
文档名称：外研版七年级上册-U5
审阅文档名：外研版七年级上册-U5（可复制到平台搜索）
```

当前平台没有可供适配器回读的稳定审阅链接，录入成功后将 `review_url_status` 标记为 `unavailable`、来源标记为 `platform_not_supported`，界面不再显示“获取失败”，而是展示可搜索、可复制的试卷/课文名称。未来接入确实提供链接的平台时，仍可异步回填 `review_url` 或明确范围的 `run_review_url`，但不能伪造链接或阻塞音频交付。

### 1.1.1 方案字段与现有工作流字段的映射

本方案的字段不能在现有工作流之外再建立一套平行身份体系。实现时应优先复用已有的工作流、工作项、音频产物和外部记录模型：

| 方案字段 | 现有模型中的对应关系 | 规则 |
| --- | --- | --- |
| `unit_id` | 结构树/工作区中的录入单元业务标识 | 标识一个逻辑录入单元，不直接等同于外部平台 ID |
| `entry_id` | 建议作为外部记录的`business_record_key` | 面向用户和脚本的稳定业务键；同一录入单元重试时不变 |
| `external_record_mapping_id` | `external_records`的本地映射主键 | 仅供本地持久化和关联使用，不作为用户展示的录入 ID |
| `external_record_id` | 外部平台实际返回的记录 ID | 创建或查询成功后保存；未知时保持为空，不能猜测 |
| `input_run_id` | 一次用户发起的批量系统录入运行；关联一个或多个`external_operation_id`，具体尝试关联`attempt_id` | 是用户可见的批次运行 ID，不替代单元级外部操作 ID |
| `structure_revision` | 关联工作流的`draft_revision`或外部目标的`target_revision_id` | 表示结构快照，不替代工作流`state_version` |
| `audio_artifact_id` | 现有音频`artifact_id` | 音频列表、下载和原文定位都引用同一个产物 ID |

如果现有数据粒度与方案中的`content_item_id`或`segment_id`不完全一致，必须建立明确的一对一或一对多映射，并保存映射关系；Renderer、解析器和后续脚本不得各自生成互不相认的本地 ID。`entry_id`、外部记录映射、外部操作和具体尝试之间的关联要能在任务重启后恢复。

### 1.1.2 术语、ID粒度与规则来源

| 术语 | 用户看到的含义 | 数据/执行含义 |
| --- | --- | --- |
| `录入类型` | 试卷、课文、词汇 | 决定配置表单、模板分类和当前版本的外部能力 |
| `试卷分类` | 听说考试、题型专项 | 只属于试卷；决定是否显示`paperType` |
| `试卷类型` | 阶段测试题、期末模拟题、单元测试题 | 只在`试卷分类=听说考试`时存在 |
| `录入单元` | 试卷中的一套，或课文/词汇中的一个单元 | 单独准备参数、单独提交和单独记录结果的最小业务对象 |
| `平台录入模板` | 外部平台提供的一整套模板 | 由`platform_template_id + template_version`引用；播放次数、间隔、准备和录音规则以平台模板为准 |
| `应用配置模板` | 用户在本应用保存的可复用配置 | 由`app_template_id + schema_version`标识；只按试卷、课文、词汇固定分类 |
| `音频批次` | 当前源文档生成的整批音频 | 覆盖整份源文档；音频质量问题必须新建任务重跑 |
| `input_run_id` | 本次批量“开始录入”的运行记录 | 一次用户启动对应一个；按录入单元关联外部操作和结果 |
| `entry_id` | 单个录入单元的录入 ID | 一个录入单元一个；系统录入意图首次确认并保存后幂等创建，重试保持不变 |

ID的固定粒度如下：

```text
一次用户点击开始录入
└─ input_run_id（批量运行）
   ├─ entry_id（录入单元A）
   │  └─ external_operation_id → attempt_id（一次或多次外部尝试）
   └─ entry_id（录入单元B）
      └─ external_operation_id → attempt_id（一次或多次外部尝试）
```

`entry_id`在用户首次确认并保存系统录入意图时创建：通常是配置中心保存“生成音频并录入系统”，或音频交付中心后置开启并保存配置；只打开抽屉但未保存时不强行创建。`input_run_id`在用户确认开始录入时创建。纯音频任务在后置开启前不创建外部录入记录。

### 1.2 第一版能力边界

| 录入类型 | 结构解析 | 音频生成 | 系统录入配置 | 外部系统录入 |
| --- | --- | --- | --- | --- |
| 试卷 | 支持 | 支持 | 第一版支持 | 第一版支持 |
| 课文 | 支持 Unit/章节/对话/语篇结构 | 按现有能力支持 | 支持（含文档自动识别建议） | 已支持（`platform_input.textbook`，1 个录入单元对应平台 1 条课文记录） |
| 词汇 | 保留通用结构，专属规则预留 | 按现有能力支持 | 保留配置容器 | 第一版暂不执行 |

三种类型都允许自动选择和手动切换，不能因为课文或词汇的外部字段暂未接入而禁用类型选择或阻止用户进入配置。只有在用户真正尝试启动外部系统录入时，才根据类型能力显示“第一版暂不支持”，不把预留配置显示成已完成。

### 1.3 版本标记和方案裁剪

本文档中的要求统一使用以下标记：

- `第一版支持`：本次可以进入产品验收和开发排期
- `预留`：数据结构和界面位置先留出，但本版本不执行真实业务
- `第一版暂不执行`：用户可以看到相关类型或结果说明，但不能启动尚未接入的外部动作

当后续章节出现相近描述时，以本章的能力矩阵和`6.3 通用录入单元数量识别`为准。示例中的`U1`、`Section A`、`Conversation 1`等只用于说明结构，不得反向改变统一的数据模型或边界判定规则。

本文档的规范优先级为：能力矩阵和术语/ID定义 → 结构与音频生命周期 → 录入单元识别 → 字段与模板规则 → 交付状态与外部执行。后续章节的示例、界面文案和验收清单只解释这些规则，不新增或覆盖规则。

## 2. 总体流程

顶部流程保持现有五步，不增加“系统录入”这个新的全局步骤：

```text
导入文档 → 内容核对 → 配置中心 → 生成任务 → 音频交付中心
```

音频交付中心内部根据配置中心已经选择的交付方式产生两条分支：

```text
音频交付中心
├─ 只生成音频
│  └─ 预览音频 → 下载音频 → 音频交付完成（系统录入未启用）
│
└─ 生成音频并录入系统
   └─ 预览音频 → 整批验收 → 复核已保存配置 → 开始自动化录入 → 最终交付
```

### 2.1 音频生成路径

用户完成文档核对和音频配置后，沿用现有的生成任务流程。

在配置中心，用户选择本次任务的交付方式：

- `只生成音频`
- `生成音频并录入系统`

选择`只生成音频`时，不展示系统录入配置。

选择`生成音频并录入系统`时，配置中心展开系统录入设置入口，用户先完成并保存系统录入配置。保存配置只代表准备录入，不代表已经提交外部平台。

### 2.2 只生成音频

用户可以直接试听、核验和下载音频，完成当前任务。

这条路径不展示系统录入配置，也不要求填写试卷、课文或词汇相关信息。

音频交付完成后，交付中心仍保留`继续录入系统`入口。此时任务的音频部分已经完成，但系统录入状态为`未启用`，用户可以在交付页面后置开启系统录入，不需要重新生成音频。

### 2.2.1 交付中心后置开启系统录入

交付中心在音频下载操作旁展示：

```text
音频交付：已生成，可试听和下载
系统录入：未启用

[下载音频]  [继续录入系统]
```

用户点击`继续录入系统`后：

- 如果用户还没有完成整批音频验收，先提示其完成整批验收；不能绕过音频确认直接提交外部平台
- 如果此前没有填写系统录入配置，打开可编辑的系统录入配置抽屉，并带入已经识别出的字段和匹配到的模板
- 如果此前已经保存过系统录入配置，默认以只读摘要展示，并提供`编辑配置`入口
- 配置确认后，复用当前任务已生成的整批音频，创建关联的系统录入运行
- 不重新生成音频，不改变已经生成的音频文件和音频验收结果

原音频生成任务的结果保持不变；后置开启的系统录入作为该任务下新增的关联运行，避免修改已经完成的音频运行记录。

### 2.3 生成音频并录入系统

用户必须先看到并试听生成的音频。

系统录入配置已经在配置中心完成。音频交付中心只负责再次展示已保存的配置，默认以只读摘要形式呈现。

用户点击`验收音频，继续录入`后，可以：

- 直接确认当前配置并进入自动化录入
- 点击`编辑配置`重新打开系统录入配置，修改并再次保存

只有配置确认完成后，系统才可以进入自动化录入。交付中心的配置复核不是重新创建配置，而是给用户一次最终检查和修改机会。

需要区分两个处理粒度：

- 音频生成和音频验收以整份源文档、整批音频为单位
- 系统录入以解析出的`录入单元`为单位；一个文档可以包含一个或多个录入单元

用户点击一次`确认配置并开始录入`即可启动当前文档的全部录入单元，系统内部按单元分别提交和记录状态。如果用户认为任意一条音频不合格，仍然不能在当前任务中只替换或重跑这一条音频，必须创建新的任务，重新执行整份文档的核对、音频生成、整批验收和后续系统录入流程。

每个录入单元在进入系统录入前都必须已经生成自己的`entry_id`，并在执行、重试、结果展示和审阅文档名展示过程中持续使用同一个 ID。单套文档只有一个录入 ID，多套文档则按每个录入单元分别生成录入 ID。

### 2.4 通用内容层级和处理粒度

`录入单元`不只服务于题型专项试卷，也适用于课文跟读和后续词汇场景。它表示一个可以独立核对、组织、交付，并在需要时作为一个整体提交给外部系统的完整逻辑块；它不等于题型，也不等于每一道题。

这三种录入类型统一使用一棵“可嵌套结构树”，不强行规定每种文档必须有完全相同的层数。固定的是录入单元和内容条目，单元中间的结构节点可以按文档实际情况出现、缺省或继续嵌套：

```text
源文档
└─ 音频生成批次（整份文档）
   └─ 录入单元（试卷 / Unit / 课文单元 / 词汇单元）
      └─ 结构节点树（可嵌套）
         ├─ 章节节点（Section / 章节 / Reading Plus）
         ├─ 内容类型节点（句子 / 段落 / 语篇 / 题型）
         ├─ 子组节点（Conversation / 语篇1 / 文章小标题）
         └─ 内容条目（可包含多个内容片段）
            └─ 音频片段
               └─ 音频产物
```

结构节点不要求固定顺序。例如课文可以是`Unit 1 → Section A → 段落跟读 → Conversation 1 → 内容条目`，试卷可以是`U5 → 模仿朗读 → 材料 → 内容条目`，而词汇未来可以是`第1课 → 词汇组 → 内容条目`。如果文档没有某一层，直接跳到下一层，不创建无意义的空节点。

不同类型的默认含义：

- 试卷：一个专项试卷或一张完整试卷是一个录入单元；部分、题型、材料和子材料按文档实际层级成为结构节点
- 课文：一个`Unit`、单元或完整课文主题是一个录入单元；`Section A`、`Understanding Idea`、`Reading for writing`等作为章节节点，句子/段落/语篇作为内容类型节点
- 词汇：预留为一个词汇单元或课次；本版本暂不展开词汇专属录入字段

`Conversation`、语篇中的多个自然段以及文章小标题，都属于结构树中的上下文节点或内容片段，不自动升级为新的录入单元。音频生成仍可以采用整批提交后切割，但切割结果必须保留完整的`录入单元 → 结构路径 → 内容条目 → 内容片段 → 音频`对应关系，不能因为合并生成而跨越单元边界，也不能把语篇内部的自然换行误拆成多个逻辑内容条目。

### 2.5 解析树与音频映射模型

解析结果需要同时保存“用户核对所看到的逻辑内容”和“音频实际切割所用的片段”。两者不能混成一个字段：

```text
结构节点（Section A / Reading Plus / Conversation 1 / 文章小标题）
└─ 内容条目（用户核对的句子、段落、语篇、题目材料或一组对话）
   └─ 内容片段（说话人句、自然段或平台要求的最小朗读单元）
      └─ 音频产物
```

- `内容条目`是用户理解和确认的逻辑单位。普通句子、普通段落通常是一条；一个`Conversation`或较长语篇可以是一条并包含多个片段
- `内容片段`是音频生成、切割和定位的最小单位，可以是对话中的一轮发言、文章的自然段，或平台模板要求的最小朗读段
- 默认不因为换行就拆条，也不因为多个片段就丢失父级上下文。界面可以按内容条目浏览，同时在条目内查看片段和对应音频
- 如果当前音频生成规则要求每个片段独立生成，就为每个片段生成一个音频；如果规则要求整段合成，则允许多个片段映射到一个合成音频，但仍保留每个片段的原文定位

每个节点、条目和片段至少保留以下信息：

| 对象 | 必要字段 | 用途 |
| --- | --- | --- |
| 录入单元 | `unit_id`、`unit_label`、`unit_order`、`unit_source_range` | 试卷、Unit 或未来词汇单元的独立核对、配置和提交 |
| 结构节点 | `node_id`、`parent_node_id`、`node_kind`、`node_label`、`node_order`、`source_range` | 还原任意层级的 Section、章节、Conversation、主题和题型 |
| 内容条目 | `content_item_id`、`content_type`、`item_order`、`raw_text`、`tts_text` | 展示完整正文、区分句子/段落/语篇/题目材料，并生成语音 |
| 内容片段 | `segment_id`、`segment_order`、`speaker_or_role`、`source_range` | 支持对话逐轮、语篇分段和精确音频定位 |
| 音频产物 | `audio_artifact_id`、`content_item_id`、`segment_id`、`artifact_type`、`lifecycle_state`、`verified`、实际格式和 MIME | 试听、下载、技术产物闸门、重跑判断和“查看对应原文” |

所有节点都要保存原文起止位置和解析置信度。`raw_text`用于保留源文档内容，`tts_text`用于保存去除序号、中文解释、结构标题和来源标签后的朗读文本；任何清洗都不能覆盖原文。

统一结构树的核心规则是：

- 层级按父子关系保存，不把`Section A`、`Conversation 1`、`句子跟读`等不同性质的文本全部塞进同一个`category`字段
- `node_kind`用于区分`unit`、`section`、`chapter`、`topic`、`content_type`、`subgroup`等角色；`node_label`保留原始显示名称
- 同一文档中可以有多个同名结构节点，但必须通过父节点和顺序区分，不能仅用名称去重
- 解析失败或无法确定归属的内容不能丢弃，先挂到最近的`待归类内容`节点，并在文稿核对中提示用户调整
- 用户手动移动、拆分、合并后的节点关系和边界必须持久化，后续重新打开、生成音频或进入系统录入时不得被自动识别覆盖

### 2.6 结构修订与音频生命周期

解析结构、音频批次和外部录入运行必须分开记录修订，不允许用户一次普通编辑把历史结果静默改掉：

- `structure_revision`：记录录入单元、结构节点、内容条目的父子关系、名称、顺序和原文范围变化
- `audio_revision`：记录`raw_text`、`tts_text`、内容片段边界或音频配置变化
- `input_run_id`：记录一次用户发起的批量外部平台录入运行；每个录入单元再关联自己的`external_operation_id`，同一操作的安全重试记录为新的`attempt_id`

按下面的规则判断是否需要重新生成音频：

| 用户操作 | 是否新建音频任务 | 处理方式 |
| --- | --- | --- |
| 只修改单元/章节显示名称 | 否 | 新增结构修订，沿用原音频；保留原始名称和修改记录 |
| 只调整节点顺序、父子关系或单元归属，且`tts_text`和片段边界不变 | 否 | 更新结构到音频的映射投影，重新确认外部录入范围即可 |
| 修改朗读文本、删除/新增内容、合并/拆分音频片段或修改音频配置 | 是 | 新建任务，整份文档重新生成音频并重新整批验收 |
| 修改系统录入配置或平台录入模板，但音频内容不变 | 否 | 生成新的配置修订；尚未产生外部副作用时沿用音频和录入单元 |
| 外部平台录入失败，且确认没有产生外部副作用 | 否 | 只重试外部录入，不重新生成音频 |

结构修订可以复用已有音频，但外部录入只能读取当前已确认的结构修订和配置版本；已经启动的`input_run_id`保持不可变。若用户因音频质量问题新建任务，必须生成新的音频批次和新的录入 ID，旧任务、旧音频验收和旧运行记录继续保留。

单元 ID按血缘关系处理：仅改名、排序或父子关系时沿用原`unit_id`；拆分后新产生的单元创建新`unit_id`，合并后只在存在明确主单元时沿用主单元 ID，否则创建新的单元 ID。已经产生外部记录的旧单元不能被合并、拆分或改写成新的外部记录，历史记录必须保留并指向旧结构修订。

外部系统录入一旦产生提交、创建或更新等副作用，当前配置版本和提交目标快照冻结。用户需要更改已冻结配置时，创建新的`input_run_id`或新任务，具体是否复用原`entry_id`由外部平台支持的“更新”语义决定；如果平台只支持创建，则使用新业务记录键，不能覆盖旧记录。

如果用户在音频生成后调整了单元边界，但没有改变内容片段和音频产物，允许沿用音频；受影响单元的系统录入配置需要重新校验，并为新增或重组后的单元重新建立`entry_id`映射。已经产生外部副作用的旧单元和旧映射保持不可变，新的单元集合只能通过新的`input_run_id`执行。

## 3. 内容核对

“内容核对”保留两个视图，不增加新的顶部步骤：

### 3.1 音频核对

保留当前已有的音频内容核对视图，用于检查：

- 文本与音频是否一致
- 音频是否完整
- 音色、语速和停顿是否合适
- 单条音频是否可以正常播放

当一个文档包含多个录入单元时，音频列表按录入单元分组展示，用户可以分别展开查看；验收动作仍然是整批验收，不提供单条音频替换或单条重跑。

音频交付需要同时通过两个独立闸门：

- **技术产物闸门**：服务端根据当前解析树生成必需音频产物清单；清单中的每个产物都具备`item_id`、`artifact_type=tts-segment`，满足`lifecycle_state=READY`、`verified=true`，且真实格式、文件扩展名和 MIME 类型一致。缺失、重复、未验证或格式不一致都不能通过；只有通过核验的产物才进入交付和系统录入。
- **用户验收闸门**：用户完成整批试听，并明确确认本批音频可以交付。

两道闸门都绑定当前`audio_revision`和音频清单摘要。至少保存`required_artifact_ids`、`artifact_manifest_hash`、`accepted_audio_revision`、`accepted_at`和验收结果；任何音频内容、片段边界、音频配置或必需产物清单变化，都必须清除旧验收并重新整批确认。

外部系统录入必须同时通过两个闸门。技术生成失败、产物缺失或格式核验失败时，可以按现有服务端`available_actions`提供安全的技术重试；这不等于允许用户只替换一条音频。任意一条音频内容质量不合格，仍按整份文档新建任务重跑。

### 3.2 文稿核对

新增`文稿核对`视图，用于展示完整文档和解析后的结构：

- 全文内容
- 题目顺序
- 题型结构
- 文档来源定位
- 分值
- 参考答案
- 音频与题目的绑定关系

分值、参考答案、题目顺序和音频绑定关系属于文档解析或系统关联结果，不属于用户在系统录入设置中重复填写的内容。

文稿核对默认以解析结果为准；已有的正文编辑、跳过或恢复动作仍需服从服务端动作和当前状态。只要修改影响`tts_text`、内容片段边界或音频配置，就使当前音频验收失效，并要求新建任务重新生成整批音频；仅调整结构归属且内容映射不变时，按`2.6 结构修订与音频生命周期`生成结构修订并沿用音频。

当一个文档中可能包含多个录入单元（例如多个专项试卷或多个课文 Unit）时，文稿核对视图还需要展示解析出的`录入单元`：

- 显示检测到的录入单元数量和每个单元的名称
- 显示每个单元覆盖的原文范围、题型模板和题目材料数量
- 支持查看单元内的题目顺序、来源标签和对应音频
- 支持对相邻内容执行`拆分为新录入单元`或`合并相邻录入单元`

`外网`、`教材`等来源标签只标记单元内的题目材料，不作为专项试卷的分组边界。

文稿核对不应只按题型建立单层列表，而应先按录入单元，再按解析出的结构树展示：

```text
录入单元
└─ 结构节点（Section / 章节 / Reading Plus / Conversation / 题型等）
   └─ 子结构节点（如有）
      └─ 内容条目
         └─ 内容片段和音频
```

用户选中一个录入单元后，再查看该单元下的结构节点和具体条目。这样试卷可以看到`U5 → 模仿朗读 → 材料`，课文可以看到`Unit 1 → Understanding Idea → 句子跟读`或`Unit 1 → Section A → 段落跟读 → Conversation 1`，三种录入类型共用同一套核对结构。

### 3.3 课文跟读的单元化核对

当前课文文档已经存在可用于分组的信息，但现有核对视图主要按`课文跟读 → 句子跟读/段落跟读/语篇跟读`展示，未把单元和章节信息作为上层结构使用。例如：

- `课文跟读-G7-1_parsed.json`包含`Understanding Idea`和`Reading for writing`两个`section`，共34条内容，内容类型包括句子、段落和语篇跟读
- `课文跟读-7上U2.docx`同样以章节为上层，再分别包含句子、段落和语篇跟读
- `课文跟读-7上-Starter Unit 1 Hello.docx`使用`Section A`和`Section B`，且部分文档没有规范的 Word 标题样式

因此，课文核对的目标结构为：

```text
课文跟读
├─ Unit 1 / U1
│  ├─ Section A 或 Understanding Idea
│  │  ├─ 句子跟读
│  │  ├─ 段落跟读
│  │  └─ 语篇跟读
│  └─ Section B 或 Reading for writing
│     ├─ 句子跟读
│     ├─ 段落跟读
│     └─ 语篇跟读
└─ Unit 2 / U2
   └─ ……
```

课文的划分规则：

- 先把整份课文文档按章节、内容类型和正文块构建成临时结构树，再依据完整章节—内容类型结构是否重复判断一个 Unit 还是多个 Unit
- `Unit 1`、`U1`、`第1单元`等标记只在单元边界已经确定后，用于命名和定位；不能单独作为拆分依据
- 如果文件名明确表示单一单元，例如`课文跟读-7上U2.docx`，则把`U2`作为名称候选，但仍需通过正文结构检查；正文中的`Understanding Idea`、`Reading for writing`作为章节结构节点
- `Section A`、`Section B`、`Understanding Idea`、`Reading for writing`、`Reading Plus`等默认作为单元内的章节结构节点，不直接拆成多张课文录入对象
- `句子跟读`、`段落跟读`、`语篇跟读`作为章节节点下的内容类型节点，不是最高层分组
- `语篇1`、语篇中的多段正文和自然换行默认属于同一个语篇条目，除非文档明确出现新的语篇编号
- 中文翻译、标题和来源说明作为条目附属信息保存，不与英文朗读正文错误合并为新的音频条目

每个课文内容条目都要保留完整映射信息：

```text
unit_id / unit_label
  → node_path（Section / 章节 / 题型 / Conversation / 子主题……）
    → content_item_id / item_order
      → segment_id / segment_order
        → audio_artifact_id
```

当前解析结果中的`section`字段不能在工作区转换、核对列表或音频结果列表中丢失；同时，`Conversation`、语篇编号、文章小标题等节点也不能被压平或丢弃。音频卡片的“查看对应原文”必须根据同一个`content_item_id + segment_id`定位到准确的英文正文；用户点击某条音频时，应能同时看到它所属的 Unit、完整结构路径、内容类型和片段上下文。

课文单元化只改变内容核对、音频组织和后续映射方式，不把试卷的省市区、试卷分类等字段套到课文配置中。

### 3.4 复杂结构的统一核对方式

内容核对页不依赖某一种文档的固定排版，而是读取解析树渲染。左侧大纲按树形展开，第一层固定为录入单元，下面按文档实际存在的节点继续展开；中间区域展示当前节点下的内容条目，右侧查看原文定位、清洗后的朗读文本和解析状态。

内容核对页顶部需要单独展示录入单元数量判定，不把它和某个名称关键词混为一谈：

```text
试卷：当前按单套组织
试卷：已识别多套（2套）
试卷：发现可能多套，待确认

课文/词汇：当前按单个录入单元组织
课文/词汇：已识别多个录入单元（2个）
课文/词汇：发现可能多个单元，待确认
```

如果显示“已识别多套/多单元”，同时展示每个候选范围的起止位置、结构重复依据和当前名称来源；如果显示“发现可能多套/多单元”，展示候选拆分线，让用户直接确认、合并或拆分。用户不需要先处理`U1/U2`等名称，也不因分组待确认而被阻止进入后续流程。

用户完成确认后，状态显示为`用户已确认单套`或`用户已确认多套（N套）`，并保留系统原始判断和用户调整记录。

以上是不同录入类型的显示文案，底层只保存一个`unit_count_status`和一组`unit_id`；“套数”和“单元数”不建立两套字段。录入类型为试卷时显示“第几套”，录入类型为课文或词汇时显示“第几个录入单元”，两者都对应同一个录入对象。

分组状态只影响外部系统录入的启动条件，不影响用户继续查看、核对、配置或生成音频：

| 自动分组状态或用户确认结果 | 内容核对 | 音频生成/下载 | 系统录入配置 | 外部系统录入 |
| --- | --- | --- | --- | --- |
| `single_default` 当前按单个单元组织 | 可用 | 可用 | 可打开和修改 | 完成配置与整批验收后可启动，并需确认按1个单元提交 |
| `multiple_confirmed` 已识别多个单元 | 可用 | 可用 | 可打开和按单元修改 | 完成配置与整批验收后可批量启动，按单元分别记录结果 |
| `multiple_candidate` 发现可能多个单元 | 可用 | 可用 | 可打开和修改 | 暂不启动；先确认、拆分或合并单元边界 |
| `user_override=single/multiple` 用户已调整 | 可用 | 可用 | 按用户结果展示 | 按用户确认后的单元集合执行 |

即使处于`multiple_candidate`，用户也可以先生成并验收整批音频；只有点击开始外部系统录入时，系统才要求本次单元边界已经明确。课文和词汇还要额外遵守`1.2 第一版能力边界`中的外部录入限制。

“开始外部录入”只有在以下条件全部满足时才可执行：录入类型支持、单元边界已确认、必需音频产物通过技术产物闸门、整批音频已通过用户验收、录入配置完整、平台录入模板可用、平台会话有效，并且服务端`available_actions`明确返回可执行动作。任一条件不满足时，界面显示具体原因和可行的下一步。

每条内容都显示一条可读的结构路径，例如：

```text
U1 / Section A / 段落跟读 / Conversation 2 / 第3个内容片段
U1 / Section B / 语篇跟读 / Conversation 1 / 第1个内容片段
U1 / Reading Plus / 语篇跟读 / The village teacher / 第2自然段
U5 / 模仿朗读 / 教材 / 材料2
```

界面规则：

- 结构节点显示名称、子节点数量、内容条目数量和解析置信度；用户可以展开、折叠和切换节点
- 选中`Conversation 1`时，先看到整段对话的上下文，再按说话人或内容片段查看各段正文和音频，不把多轮对话误显示成互不相关的句子
- 选中文章小标题时，展示该小标题下的完整语篇范围；小标题是语篇内部结构，不自动生成新的 Unit 或新的录入对象
- 句子、段落、语篇、题目材料的展示方式可以不同，但都落到同一套`内容条目 → 内容片段 → 音频`模型上
- 用户可以对相邻内容执行拆分、合并或移动到相邻结构节点；操作后保留新的父子关系和原文范围
- 结构识别不确定时，只标记待确认并提供调整入口，不阻止用户继续查看音频或进入配置中心

全文视图和结构视图使用同一份解析数据：全文视图负责核对原文连续性，结构视图负责核对层级、条目和音频映射。用户在任一视图修改或确认后，另一视图同步更新，避免出现“全文一套内容、音频列表另一套内容”的情况。

## 4. 配置中心

### 4.1 音频配置

配置中心默认只展示现有的音频配置，例如：

- 音色
- 语速
- 音调
- 音量
- 音频格式
- 生成质量
- 生成范围或生成模式

不在默认页面一股脑展示系统录入配置。

### 4.2 系统录入配置

当用户在配置中心选择`生成音频并录入系统`后，才展示系统录入配置入口。

系统录入配置可以使用右侧抽屉承载，包含录入类型和对应的类型配置。用户保存后，配置进入当前 workflow 的持久化配置，并产生配置版本。

配置中心的系统录入设置承担常规情况下的“首次配置”职责；对于已经保存过配置的任务，音频交付中心只承担“最终复核”职责。对于此前选择`只生成音频`、从未保存系统录入配置的任务，交付中心的`继续录入系统`入口可以启动同一套配置抽屉，完成后续的首次配置。

如果源文档解析出多个录入单元，配置中心采用`公共默认配置 + 单元配置`：

- 省市区、学段、年级、年份、答题时长等可以先填写一次，作为全部单元的默认值
- 每个录入单元都保存独立的录入 ID、结构标签和配置；结构标签在单元边界确定后生成，优先使用单元内可靠标记，没有可靠标记时使用“试卷 1”等序号标签。试卷名称必须由用户填写，不因切换、保存或同步自动生成、覆盖
- 录入题型模板按单元保存，公共模板可以批量应用，但不能把多个单元合并成一个外部录入记录
- 用户可以使用`应用到全部录入单元`批量设置，也可以展开任意单元单独修改
- 单元配置最终独立提交，某个单元的修改不会覆盖其他单元

只有一个录入单元时，界面保持当前单试卷表单，不额外增加分组操作。

如果用户选择`只生成音频`，系统录入配置区域保持隐藏，用户不需要填写试卷、课文或词汇相关信息。

### 4.3 抽屉交互

系统录入设置使用右侧抽屉承载，不新增独立顶部步骤，也不优先使用会遮挡音频内容的弹窗。

抽屉的好处：

- 音频交付中心的试听内容仍然可见
- 配置中心和交付中心可以复用同一套表单
- 交付中心默认只展示摘要，不强迫用户重新填写
- 不增加新的流程节点
- 后续可以根据录入类型动态切换表单

当用户从音频交付中心后置点击`继续录入系统`时，仍然打开同一个系统录入配置抽屉。这样既能复用配置中心的表单，也能处理用户之前没有填写过录入配置的情况。

当录入单元较多时，抽屉首屏只展示类型、模板匹配结果、公共默认值和各单元的完成度，不一次展开所有单元的完整表单。用户点击某个单元后再展开差异字段；批量修改使用明确的`应用到全部录入单元`动作，并在应用前说明会影响哪些单元。这样既保留多单元能力，也避免配置中心变成一张过长的重复表单。

### 4.4 可访问性与大文档表现

- 抽屉打开后焦点进入标题或第一个可编辑控件，按`Escape`关闭并恢复到触发按钮；所有字段、模板选择和单元展开操作都支持键盘完成
- 识别冲突、音频验收、外部录入进度和失败原因同时提供文字状态和可读播报，不只依赖颜色或图标
- 多单元或大文档默认折叠结构节点，按需加载条目和音频列表；用户可以搜索、按单元筛选，不要求一次渲染全文所有音频
- 在窄窗口和放大显示下，关键动作、当前状态和错误原因不能被横向滚动隐藏；状态文本保持完整可读

## 5. 录入类型和自动识别

系统录入类型分为三类：

```text
录入类型
├─ 试卷
├─ 课文
└─ 词汇
```

三种类型全部保持可点击、可手动切换。自动识别只负责默认选择，不做流程限制，也不会因为识别结果而禁用其他类型。

用户手动切换录入类型后：

- 使用用户最终选择的类型
- 只切换系统录入设置的表单结构
- 不重新生成音频
- 不改变文档解析结果
- 不阻止后续流程继续执行

当前版本的类型范围：

- 试卷：完善当前平台所需的录入配置
- 课文：完善按 Unit/章节的内容解析、核对和音频组织；系统录入专属字段仍保留配置容器，暂不套用试卷字段
- 词汇：保留类型选择、模板筛选和配置容器，暂不定义专属字段

课文和词汇不能套用试卷字段，也不能因为专属字段暂未定义而禁用类型选择。课文的单元化解析、内容核对和音频分组属于当前版本的基础能力，不等同于已经完成课文的外部系统录入字段。类型切换不影响音频生成和音频交付；系统录入执行时，只根据对应类型已经接入的平台能力判断配置是否可用，不展示虚假的“配置已完成”。

### 5.1 录入类型识别规则

识别优先使用文档内容和结构，文件名只作为辅助信息。

| 文档特征 | 默认录入类型 |
| --- | --- |
| 包含听后选择、听后应答、模仿朗读、信息转述等考试题型 | 试卷 |
| 包含句子跟读、段落跟读、语篇跟读 | 课文 |
| Excel 中存在“单词”“例句”等词汇字段 | 词汇 |

当前项目文档中，`课文跟读-*.docx`应识别为课文，`U6单词导入模板.xlsx`应识别为词汇，其他包含考试题型的 Word 文档应识别为试卷。

## 6. 录入单元和试卷分类识别

当录入类型为`试卷`时，继续识别试卷分类。

内置分类：

- `听说考试`
- `题型专项`

第一版只保留平台已经确定的内置试卷分类，不开放用户创建新的试卷分类。

### 6.1 听说考试

满足以下特征时，默认识别为`听说考试`：

- 文档包含多个考试题型模块
- 文档具有完整试卷结构
- 文件名包含“听说考试”“听说测试题”“新题型”等内容
- 文档内容同时出现多个听说题型

例如：

- `七上Starter Unit 1 听说测试题（2026新题型）`
- `佛山七上Starter 1`

### 6.2 题型专项

满足以下特征时，默认识别为`题型专项`：

- 文档只包含一种主要考试题型
- 文件名包含“专项”
- 文件名明确指向模仿朗读、听后选择、听后应答等单个题型

例如：

- `模仿朗读-7上-U5-U6`
- `听后选择-7上 Starter Unit 1 Hello!`
- `S1-听后应答`

“模仿朗读”“听后选择”“听后应答”等属于录入题型模板，不属于试卷分类。

试卷分类的判断以正文结构和题型组合为主，文件名中的“听说考试”“专项”等只作为辅助证据。若结构证据与文件名冲突，保留候选结果并标记`paper_category_status=conflict`，不能仅凭文件名自动确认；用户手动选择后，才把分类写入当前配置。

### 6.3 通用录入单元数量识别

自动识别的第一步不是寻找`U1`、`U2`、`Section`或`Conversation`，而是先把整份源文档暂时看成一个整体，判断其中是否存在多个可以独立成立的完整结构块。这里的“录入单元”在试卷场景表现为一套试卷，在课文场景表现为一个课文 Unit，在词汇场景表现为一个词汇单元。

推荐采用“临时整文档树 + 候选分组竞争”的方式：

```text
整份源文档（暂不指定录入单元）
  → 提取连续内容块和结构节点
  → 生成题型/内容结构签名
  → 同时评估“单个录入单元”和“多个录入单元”假设
  → 校验每个候选分组的完整性、独立性和边界
  → 选择当前最合理的分组结果
  → 再用 U、Section、Conversation、文章标题等标记命名和细化层级
```

结构签名至少包含以下信息：

- 规范化后的题型或内容类型，例如`模仿朗读`、`句子跟读`、`段落跟读`、`语篇跟读`
- 类型出现的顺序，以及前后相邻的类型组合
- 答题说明或任务说明的语义摘要
- 材料形态和数量，例如外网/教材材料、句子数量、段落数量、对话轮次、语篇数量
- 编号是否重新开始、题型标题是否重新出现、正文是否形成新的连续内容块
- 版面分隔、空行、分页等辅助边界信息

单独出现一次相同题型不能判定为多套。题型重合只是发现候选分组的入口，还必须检查它是否和说明、顺序、材料形态、编号重启等共同构成一套新的完整结构，并且前后范围彼此独立。这样可以避免把一套课文中的多个`Conversation`、`Section A/B`或多个语篇误拆成多个录入单元。

系统不要只维护“单套/多套”一个结论，还要区分自动判断和用户确认：

实现上只维护一个`unit_count_status`字段，并由一组`unit_id`承载具体对象；“单套/多套”和“单元/多单元”只是录入类型不同的界面文案。

| 自动状态 | 试卷场景显示 | 课文/词汇场景显示 | 含义 |
| --- | --- | --- | --- |
| `single_default` | `当前按单套组织` | `当前按单个录入单元组织` | 没有足够的多套证据，先按一个单元展示；不代表绝对只有一套 |
| `multiple_confirmed` | `已识别多套（N套）` | `已识别多个录入单元（N个）` | 发现两个或以上高置信度、边界独立的完整结构块 |
| `multiple_candidate` | `发现可能多套，待确认` | `发现可能多个单元，待确认` | 存在部分重复或边界冲突，需要用户确认 |

用户确认后单独记录`user_override=single`或`user_override=multiple`，不要覆盖自动判断结果。这样既能保留解析依据，也能保证用户手动选择永远优先。

核对页默认显示的是“录入单元判定”，试卷类型下可以将其简称为“试卷套数判定”。不使用`U1识别成功`、`Section识别成功`或`Conversation识别成功`作为套数结论，因为这些只是结构标记，不代表独立录入单元。

候选分组确定后，再按每个范围内的标记生成单元结构标签：

- 块内有明确且与该范围对应的`U5`、`U6`等标记时，显示为`U5`、`U6`，并保留原文标签
- 没有可靠名称时，按录入类型生成稳定的卡片标签，例如`试卷 1`、`试卷 2`、`课文单元 1`、`课文单元 2`；这些标签只用于识别录入边界，不自动写入试卷名称
- `Section A/B`、`Conversation 1/2`、`语篇1/2`和文章小标题只放入结构路径，不用于替代试卷或课文单元名称
- 名称识别失败不影响分组边界；用户可以修改显示名称，但不能因为改名而改变原文边界

以下情况默认按一个单元组织，而不是拆成多套：

- 同一章节内重复出现`句子跟读`、`段落跟读`或`语篇跟读`
- 一个`Section`下出现多个`Conversation`
- 一个语篇下出现多个文章小标题或自然段
- 同一套试卷内重复出现`外网`、`教材`等材料来源标签
- 题型编号在同一题型内部重新从1开始，但没有新的完整结构和独立说明

以下情况进入`multiple_candidate`，不阻止用户继续进入内容核对、配置中心或音频生成：

- 只重复了部分题型，无法确认是否构成完整的一套
- 前后结构高度相似，但材料范围或边界互相重叠
- 题型顺序被打乱，无法可靠还原每套的起止位置
- 只有`U1/U2`等名称变化，没有足够的结构证据

用户在文稿核对中可以查看候选边界、拆分、合并和移动内容；用户调整后的结果优先于自动判定，并在后续重新解析时保持不变。

### 6.4 自动识别原则

系统不承诺所有普通文件名都能百分之百判断，因此采用以下方式：

- 能确定的直接填入
- 只能推测的作为默认建议
- 无法判断的字段保持为空，并标记为`待确认`
- 用户始终可以手动修改
- 用户手动修改后，以用户选择为最终结果

识别状态固定为：

- `已确认`：文档或模板提供了明确结果
- `待确认`：系统给出了高可能性建议，但需要用户确认
- `未识别`：没有足够信息，保持为空
- `用户修改`：用户已手动修改，自动识别不得覆盖

界面中需要同时显示识别来源和依据，例如：`文档识别`、`应用配置模板带入`、`用户修改`、`待确认`。

字段识别状态与录入单元数量状态分开保存：字段继续使用上述`已确认/待确认/未识别/用户修改`，单套、多套的自动结果使用`6.3 通用录入单元数量识别`中的状态，避免把“识别到一个名称”误显示成“确认只有一套”。

每个自动识别字段和每个录入单元边界都需要保存`confidence_band=HIGH|MEDIUM|LOW`以及`evidence[]`。证据至少包括结构签名、独立内容范围、题型或内容类型顺序、编号重启、页面或段落分隔、标题层级和可选节点缺失情况：

- `HIGH`且没有冲突时，可以作为默认已确认值展示
- `MEDIUM`或存在多个竞争解释时，展示建议和证据，并要求用户在外部录入前确认
- `LOW`时不自动填入高风险字段，也不自动拆分；使用空值、默认单元或`待确认`状态

不同录入单元可以缺少某个可选的 Section、题型或内容节点，只要各自的内容范围和边界独立，不能因为结构不完全相同就判定为无法分组。关键词只能作为证据之一，不能单独提高到`HIGH`。

### 6.4.1 类型冲突和解析覆盖

录入类型、试卷分类和录入单元数量是三个独立判断，不能用其中一个结果代替另外两个。至少保存以下状态：

| 状态 | 可选值 | 用途 |
| --- | --- | --- |
| `input_type_status` | `suggested`、`confirmed`、`conflict`、`user_override` | 表示试卷/课文/词汇的自动建议和用户最终选择 |
| `paper_category_status` | `suggested`、`confirmed`、`conflict`、`user_override` | 仅试卷使用，表示听说考试/题型专项的识别状态 |
| `parse_coverage_status` | `complete`、`partial`、`unclassified` | 表示源文档内容是否都已进入解析树；明确标记为辅助内容并移出本次目标后，重新计算目标范围 |

出现类型或分类冲突时，界面保留最可能的默认选择并展示证据，用户可以直接手动切换；手动切换只改变录入配置类别，不重新生成音频，也不改写原始解析树。未解决的冲突不阻止用户进入配置和生成音频，但外部录入前必须确认最终类型、分类及其字段映射。

解析器必须统计源文档块和解析结果的覆盖情况：`source_block_count`、`parsed_block_count`、`unclassified_count`、`ignored_auxiliary_count`和未归类内容的原文范围。`complete`表示目标范围内的内容都已进入解析树，或已被用户明确标记为辅助内容并记录移出原因；`partial`表示仍有内容只完成了部分解析或映射，`unclassified`表示内容角色尚未识别。未归类或未完成映射的内容可以保留在待归类节点中继续核对，但确认前不能被当作完整的外部录入目标；界面要显示具体数量和位置，而不是只显示笼统的“解析完成”。

### 6.5 一个文档包含多个专项试卷

试卷分类识别和文档分组识别是两个不同层次：

- `试卷分类`回答“这些内容属于听说考试还是题型专项”
- `录入单元`回答“外部平台需要创建几张独立的试卷，以及每张试卷包含哪些题目”

试卷分类为`听说考试`时，显示并要求选择`paperType`；试卷分类为`题型专项`时不显示该字段，提交载荷也不得携带历史残留的`paperType`。如果用户从`听说考试`切换为`题型专项`，应立即清空界面值；切回`听说考试`后重新要求选择。

一个源文档可以生成一个音频批次，但可以解析出多个录入单元。对题型专项文档，识别顺序如下：

1. 先识别题型、答题说明、材料形态和编号结构，生成每个连续题型块的结构签名
2. 比较前后是否重复出现一套完整或高度完整的题型结构；仅重复出现某个题型标题或“外网/教材”标签时，不单独拆分
3. 以重复结构块的起止范围作为多套候选边界，并用页面分隔、标题层级、编号重新开始等版式信号辅助校验
4. 在边界已经确定后，才读取块内的`U5`、`U6`、`第1套`、`试卷二`、`专项一`等文本作为单元名称；文件名和文档总标题只作为名称或上下文辅助信息，不能单独决定分组

在旧版音频-only U/来源版式中，反复出现的`外网`、`教材`等材料来源标签不应拆成新的试卷；它们属于当前录入单元内的题目材料。若命中带分值的`模仿朗读`大题标题这一独立画像，则每个来源段落本身就是一份录音稿，应按该画像拆成独立试卷。

以`模仿朗读-7上-U5-U6.docx`为例，因 U5/U6 的大题标题都明确写出“共 6 分”，系统应默认识别为：

| 层级 | 识别结果 | 后续用途 |
| --- | --- | --- |
| 源文档 | 7年级上学期模仿朗读试题 | 生成一个整批音频 |
| 录入单元 1–2 | U5，2段外网录音稿 | 每段各作为一张专项试卷录入，题目分值均为 6 分 |
| 录入单元 3 | U5，1段教材录音稿 | 作为一张专项试卷录入，题目分值为 6 分 |
| 录入单元 4–5 | U6，2段外网录音稿 | 每段各作为一张专项试卷录入，题目分值均为 6 分 |
| 录入单元 6 | U6，1段教材录音稿 | 作为一张专项试卷录入，题目分值为 6 分 |

该文档共包含6个录入单元和6段题目材料。以下名称只能作为用户手动填写时的参考，不自动写入试卷名称字段：

```text
7年级上学期-U5-外网-第1稿-模仿朗读
7年级上学期-U5-外网-第2稿-模仿朗读
7年级上学期-U5-教材-第1稿-模仿朗读
7年级上学期-U6-外网-第1稿-模仿朗读
7年级上学期-U6-外网-第2稿-模仿朗读
7年级上学期-U6-教材-第1稿-模仿朗读
```

如果文档没有明确的分组标记，系统根据结构生成候选分组并标记为`multiple_candidate`；如果无法可靠分组，默认按一个录入单元展示，同时允许用户在文稿核对中拆分或合并。分组识别不阻止用户进入配置中心，但在系统录入前必须让用户看到本次将要录入的单元数量和内容范围。

分组结果需要保存原文起止位置、单元标识、题目 ID 和音频 ID。用户手动拆分或合并后，后续自动识别不得覆盖用户结果。

### 6.6 课文单元识别

课文文档的录入类型仍然是`课文`，是否包含多个 Unit 不改变类型识别结果。课文单元数量也遵循`6.3 通用录入单元数量识别`：先比较完整的章节—内容类型结构是否重复，再判断是一个 Unit 还是多个 Unit。系统需要在单元数量判定之后，用以下标记补充名称和层级：

- `Unit 1`、`U1`、`第1单元`等标记只用于为已经确定的结构块命名和定位
- 文件名明确指向单一单元时，例如`课文跟读-7上U2.docx`，可以作为单一单元的名称候选，但不能绕过正文结构检查
- 未出现明确 Unit 标记但整份正文只有一套章节—内容类型结构时，创建一个默认单元；不能因为存在多个`Section`或`Conversation`就误拆成多个单元
- `Section A/B`、`Understanding Idea`、`Reading for writing`和`Reading Plus`作为单元内章节结构节点
- `句子跟读`、`段落跟读`、`语篇跟读`作为章节节点下的内容类型节点；如果文档缺少章节节点，则直接挂在单元下

多个课文单元需要保留独立的单元顺序、原文范围、内容条目和音频映射。即使识别到`U1/U2`，只要完整结构没有重复，也不能直接判定为多个单元；这种情况先按一个单元组织，只有同时存在其他冲突证据时才进入“发现可能多个单元，待确认”。单元识别不阻止用户进入配置或生成流程；低置信度结果在文稿核对中标记为`待确认`，用户可以拆分或合并相邻单元。

### 6.7 复杂课文的结构识别

三份样例说明，课文跟读不能只解析成“句子、段落、语篇”三种平铺题型，必须同时识别单元、章节、内容类型、对话或主题子组，以及这些节点下的正文片段：

| 样例 | 识别出的录入单元 | 结构节点 | 内容条目或片段 |
| --- | --- | --- | --- |
| `课文跟读-7上-Starter Unit 1 Hello.docx` | `Starter Unit 1` | `Section A`、`Section B`；其中有`段落跟读 → Conversation 1/2/3`和`语篇跟读 → Conversation 1/2` | Conversation下按说话人或连续段落保留多个片段 |
| `课文跟读-G7-3.docx` | `U3` | `Understanding Idea`、`Reading for writing`；每个章节下再有句子、段落、语篇，语篇下有`语篇1/语篇2` | 语篇保留完整逻辑条目，内部自然段按需要作为内容片段 |
| `课文跟读人教九上U1.docx` | `U1` | `Section A`、`Section B`、`Reading Plus`；`Reading Plus`下有`The watermelon farmer`、`The flower live-streamer`、`The village teacher` | 文章小标题作为语篇子组，下面保留对应自然段 |

这三类文档统一落成如下结构，不为每一种排版单独发明一套数据模型：

```text
课文跟读
└─ U1 / Starter Unit 1
   ├─ Section A
   │  ├─ 句子跟读
   │  │  └─ 内容条目 → 内容片段 → 音频
   │  └─ 段落跟读
   │     ├─ Conversation 1
   │     │  ├─ 说话人A的第1段 → 音频片段
   │     │  └─ 说话人B的第1段 → 音频片段
   │     └─ Conversation 2
   ├─ Section B
   │  └─ 语篇跟读
   │     └─ Conversation 1 → 多个内容片段 → 音频
   └─ Reading Plus
      └─ 语篇跟读
         ├─ The watermelon farmer → 多个自然段
         ├─ The flower live-streamer → 多个自然段
         └─ The village teacher → 多个自然段
```

解析器应按以下优先级判断边界和角色：

1. 先读取并规范化正文块，识别章节、题型、对话、语篇和正文内容，形成有顺序的结构签名；此阶段不因为出现`U1`、`Section A`或`Conversation 1`就创建新录入单元。
2. 比较完整结构签名，先判定当前文档是按单个课文单元组织，还是存在多个重复课文单元；结构重复不足且没有冲突证据时使用`single_default`，不强行拆分，只有边界存在竞争解释时才使用`multiple_candidate`。
3. 在单元边界确定后，将`Unit/U/第X单元`作为单元名称候选，将`Section A/B`、`Understanding Idea`、`Reading for writing`、`Reading Plus`作为章节节点。它们是内容结构，不是新的录入类型，也不是新的试卷。
4. 识别`句子跟读`、`段落跟读`、`语篇跟读`或其他明确题型，作为内容类型节点；未来出现其他题型时沿用同一节点机制。
5. 在段落或语篇下识别`Conversation 1`、`Conversation 2`、`语篇1`、`语篇2`和文章小标题，作为可嵌套的子组节点。它们只有在文档明确出现时创建，不根据数量猜测。
6. 在子组下识别连续正文、说话人标签、编号和自然段，形成内容条目和内容片段；中文翻译、提示语、来源说明保留为辅助字段，不混入`tts_text`。
7. 每个节点都记录来源段落范围和置信度。无法判断的标题或正文先挂在最近的父节点下，并标记`待确认`，不因为解析不确定而丢弃内容。

`Conversation`的处理尤其需要区分三个概念：

- `Conversation 1`是对话子组，负责把多轮内容放在同一个上下文中
- 每一轮说话或连续的对话段是内容片段，可以带`speaker_or_role`；它通常对应一个独立音频，但不强制绑定某一种生成策略
- 整段对话仍然可以作为一个内容条目用于全文核对和系统映射；如果平台需要整段提交，则由多个片段聚合成一个逻辑音频或录入内容

因此，不能使用“遇到一个`Conversation`就新建一个课文录入对象”或“遇到一次换行就新建一条音频”这种规则。正确的做法是保留父级对话、子级片段和原文位置，让音频生成策略在不破坏结构映射的前提下决定一条还是多条音频。

同一套解析原则也适用于试卷和词汇：试卷中的章节、部分、题型、材料和子材料落为结构节点；词汇未来可以将课次、词汇组、词条例句落为结构节点和内容条目。类型识别不同只影响可接受的节点词和录入配置，不影响底层树形结构、核对方式和音频映射。

## 7. 试卷录入配置

试卷类型的系统录入设置包含以下字段：

- 试卷名称
- 试卷分类
- 省份
- 城市
- 区/县
- 学段
- 年级
- 年份
- 大约答题时长
- 录入题型模板

试卷字段以`录入单元`为最终提交对象。单个单元时沿用现有单试卷表单；多单元文档使用公共默认值减少重复填写，并允许单元级覆盖。

字段来源和填写要求：

| 字段 | 默认作用范围 | 主要来源 | 要求 |
| --- | --- | --- | --- |
| 试卷名称 | 单元级 | 文档名称、单元标记或文件名 | 必填，每个单元独立保存 |
| 试卷分类 | 文档识别默认值，单元级保存 | 文档结构、文件名、应用配置模板、用户选择 | 必填 |
| 省份、城市 | 文档级默认值，可单元级覆盖 | 地区字典匹配、文档、应用配置模板、用户选择 | 必填 |
| 区/县 | 文档级默认值，可单元级覆盖 | 地区字典匹配、文档、应用配置模板、用户选择 | 非必填 |
| 学段、年级 | 文档级默认值，可单元级覆盖 | 文档、应用配置模板、用户选择 | 必填，年级受学段过滤 |
| 年份 | 文档级默认值，可单元级覆盖 | 文档、文件名、应用配置模板、用户选择 | 必填 |
| 大约答题时长 | 文档级默认值，可单元级覆盖 | 文档、应用配置模板、用户选择 | 必填，单位为分钟 |
| 录入题型模板 | 单元级，可批量应用 | 平台录入模板、文档题型识别、应用配置模板、用户选择 | 必填 |

以下内容不配置：

- 试题分值
- 参考答案
- 音频与题目绑定关系
- 播放次数
- 播放间隔
- 准备时间
- 录音时间
- 试卷难度

播放次数、播放间隔、准备时间和录音时间由外部平台选择的题型模板提供。试卷难度使用平台默认值。

这里的“录入题型模板”指向外部平台的一套完整录入模板，底层建议保存为`platform_template_id`；它负责播放次数、播放间隔、准备时间、录音时间等规则。它不等同于本应用中用户保存的“应用配置模板”，后者只保存试卷的地区、学段等可复用元数据和模板选择结果，不保存当前试卷名称。

## 8. 省、市、区县数据

省市区使用用户提供的完整三级树形数据，不只维护少量示例数据。

完整原始数据见：[省市区完整数据附件](</Users/asklins/.codex/attachments/d6141a63-ff86-4e7d-8f7d-ff32a40576d8/pasted-text.txt>)。该附件中的`data`数组就是本方案的完整地区数据来源。

该绝对路径只用于本次方案审阅，不应作为发布后依赖。实现时必须把附件中的完整`data`数组落地为项目内的稳定地区字典，建议作为本地静态快照，并在接口可用时进行更新或校验：

```text
electron/renderer/data/region-tree.json
```

`region-tree.json`建议使用`{ "version": "...", "data": [...] }`外壳，完整保留每个地区的`id`、`name`、`parentId`、`level`、`sort`、`createTime`和`children`；接口返回的`code`、`msg`不作为地区节点数据。完整地区数据必须原样纳入，不能只保留本文档中的示例记录。

落地或更新地区字典时增加一次离线校验：

- 省级、城市、区县数量分别为`31 / 341 / 3042`
- 所有 ID 唯一，三级节点的`parentId`必须存在且层级正确，不允许孤儿节点或循环引用
- `children`与`parentId`双向一致，`level`只能为1、2、3
- `sort`在同一父节点下稳定，直辖市的省级 ID和市级 ID保留，不按同名合并
- 快照保存来源版本或校验摘要，接口更新前先通过校验，再替换当前字典

地区附件的临时绝对路径只用于本次方案核对，不能进入运行时配置或发布说明。开发验收必须同时检查项目内的`region-tree.json`实际存在、能够被应用读取，并记录快照版本和校验摘要；其中省级节点允许使用根节点约定的`parentId=0`，不把它误判为孤儿节点。

该数据当前包含：

- 31 个省级地区
- 341 个城市
- 3042 个区县

### 8.1 数据结构

`region-tree.json`文件根部使用`version + data`，下面是`data`数组中一个省级节点的示例：

```json
{
  "id": 110000,
  "name": "北京市",
  "parentId": 0,
  "level": 1,
  "sort": 0,
  "createTime": 1775204415000,
  "children": [
    {
      "id": 110100,
      "name": "北京市",
      "parentId": 110000,
      "level": 2,
      "children": [
        {
          "id": 110101,
          "name": "东城区",
          "parentId": 110100,
          "level": 3,
          "children": null
        }
      ]
    }
  ]
}
```

层级定义：

- `level=1`：省、自治区、直辖市
- `level=2`：城市
- `level=3`：区、县
- `parentId`：父级行政区 ID
- `children`：下级地区；三级地区通常为`null`

提交给外部平台时使用 ID，界面展示使用名称：

```json
{
  "provinceId": 440000,
  "cityId": 440600,
  "districtId": 440605
}
```

`code`、`msg`属于接口响应外壳；`createTime`保留数据即可，不参与用户配置展示。

### 8.2 地区选择交互

- 选择省份后，只展示该省下的城市
- 选择城市后，只展示该城市下的区县
- 更换省份时清空城市和区县
- 更换城市时清空区县
- 区/县为非必填项
- 北京、上海、天津、重庆等直辖市保留省级 ID 和市级 ID，不能因为名称相同而合并
- 省市区支持关键词搜索，并显示完整路径，例如`广东省 / 佛山市 / 南海区`
- 搜索区县时优先展示完整父级路径，避免同名地区误选

### 8.3 地区自动识别

只在文档或文件名出现明确地区名称时自动填充：

- `佛山`可识别为广东省、佛山市
- `南海`在已识别佛山市的前提下可识别为南海区
- `禅城`在已识别佛山市的前提下可识别为禅城区

如果地区信息不明确，不根据电脑所在地、历史任务或用户 IP 猜测。

## 10. 应用配置模板

系统录入设置支持用户保存“应用配置模板”。应用配置模板只保存本应用的录入元数据和配置选择，不复制外部平台录入模板中的播放、准备和录音规则。

用户可以：

- 填写一套系统录入配置
- 自定义模板名称
- 模板归档分类由录入类型自动确定
- 后续选择模板直接带入配置
- 修改后保存为新模板或更新原模板

应用配置模板只分为三类：`试卷`、`课文`、`词汇`。用户选择录入类型后，只展示对应类型的模板，不展示其他类型模板。

模板归档分类不允许用户自由创建，也不与“听说考试/题型专项”这样的试卷分类混用。

多单元文档使用应用配置模板时，用户可以选择将模板带入当前单元或全部单元；默认只作用于当前选中的单元。配置一致的单元可以由同一条公共模板批量带入，配置不同的单元按各自对应的模板带入；用户可以继续单独修改某个单元。应用配置模板仍然不保存题目正文、音频或解析结果。

### 10.1 应用配置模板保存内容

应用配置模板可以保存：

- 录入类型
- 当前录入类型对应的字段，例如试卷的分类、试卷类型、省市区、学段年级、年份、答题时长和录入题型模板
- 课文或词汇未来增加的专属配置
- `app_template_id`、模板结构版本、创建时间和更新时间
- 所选`platform_template_id`、平台模板显示名、平台模板版本或校验摘要（只保存引用和快照元数据，不复制播放规则）

应用配置模板按录入类型使用不同的字段集合：试卷模板不带入课文、词汇字段，课文和词汇模板也不显示或伪造试卷字段；同一套模板结构只在对应类型的配置抽屉中生效。

模板名称可以由用户自定义，但模板所属分类由录入类型自动确定。

应用配置模板不保存当前文档的：

- 题目正文
- 分值
- 参考答案
- 音频文件
- 音频绑定关系
- 文档解析结果

从多单元任务保存应用配置模板时，先忽略试卷名称，再比较各单元的可复用配置。如果所有单元的配置一致，只保存一条公共应用模板；如果除名称外存在配置差异，则按不同配置分别保存多条应用模板，每条模板只保存对应单元的配置。单元名称、原文范围、题目内容和单元专属任务事实不保存到模板。

### 10.2 应用配置模板自动匹配

应用配置模板匹配条件包括：

- 录入类型
- 当前录入类型下可用的分类、类型、地区、学段年级和平台录入模板字段
- 用户最近使用记录

自动匹配时，只在当前录入类型对应的应用配置模板中查找。

如果只有一个高匹配应用配置模板，系统将其作为建议；如果有多个候选模板，默认推荐最近使用的模板，用户可以切换。自动匹配只补全缺失字段，不改变文档明确值；如果用户在配置中心明确点击应用模板，则将模板作为待应用值，并以字段冲突提示让用户确认，确认后的字段值视为用户当前手动选择。多单元文档按录入单元分别匹配平台录入模板和应用配置模板；公共配置可以由同一条模板带入，存在差异的单元使用各自模板。某个单元的用户修改只影响该单元。

应用配置模板匹配优先使用相对稳定的配置条件：录入类型，以及该类型下实际存在的分类、类型、地区、学段、年级和平台录入模板字段。试卷名称、年份和当前文档内容属于任务数据，默认不参与模板匹配；年份可以从当前文档或模板带入，但不能因为年份不同而排除同一套应用配置模板。用户最近使用记录只用于多个候选模板的排序。

应用配置模板带入的数据只用于补全缺失配置，不覆盖文件中已经识别出的字段，也不覆盖用户当前手动修改的字段。模板应用前需要逐字段展示`value`、`source`、`confidence`和`locked`状态；发生冲突时，让用户选择“保留文档值”或“使用模板值”，不能静默覆盖文件中的明确内容。

如果保存的`platform_template_id`已失效、版本不可用或当前账号无法访问，模板仍可以展示为历史模板，但不能伪造为可执行模板；当前任务必须提示用户重新选择可用的平台录入模板后，才能开始外部录入。

应用配置模板应用到当前任务时使用副本，不直接修改原模板。单套任务直接应用到当前目标；多套任务应用前由用户选择“当前单元”或“全部单元”，默认选中当前单元；选择全部时需要确认受影响的单元数量，其他单元只有在明确确认后才会改变。系统录入配置保存到当前 workflow，并随配置版本持久化；一旦外部录入开始，当前配置版本冻结。

应用模板到多单元任务时，需要明确展示应用范围：选择“当前单元”只影响正在编辑的单元；选择“全部单元”才将模板带入所有单元，单元名称和文档内容继续保留；如果会覆盖已有单元配置值，先展示受影响的单元数量和字段差异，再由用户确认。保存新模板和更新原模板都产生新的模板版本，历史任务继续引用当时的`app_template_id + schema_version`快照。

## 11. 字段来源和优先级

自动填充阶段，单个字段的默认值按以下优先级确定：

```text
文件名或文档中的明确内容
    >
自动匹配的历史应用配置模板
    >
文档结构推断
    >
空值
```

其中：

- 文件名或文档明确写出的内容优先级高
- 应用配置模板主要用于补齐没有识别到的内容；其中的平台录入模板字段仍需校验当前平台模板是否可用
- 用户明确应用模板后，对冲突字段逐项确认；用户确认结果和之后的手动修改高于上述所有自动来源
- 自动推断只能作为默认值
- 出现冲突时提示用户，不静默覆盖
- 用户一旦手动修改，后续自动识别不得覆盖

录入单元分组也遵循同样原则：用户手动拆分或合并的结果优先于文档中的明确分组标记，系统后续重新解析时不得静默改回自动结果。

## 12. 音频交付中心的界面状态

音频交付中心继续复用现有的音频列表、播放器、下载、进度和日志区域，在内部增加系统录入状态。

推荐状态：

- 音频生成中
- 待整批音频验收
- 待系统录入配置确认
- 待开始自动化录入
- 系统录入中
- 录入完成
- 录入失败，可安全重试
- 录入结果待确认
- 系统录入未启用
- 音频已交付，系统录入未完成

### 12.1 状态分层和多单元汇总

交付中心不使用一个状态字段同时表示解析、音频和外部录入。下面这些是面向用户的状态投影，不替代现有服务端工作流、工作区条目、产物和外部操作状态；其中只有当前需要用户处理的状态才展示为主提示，其他状态收进详情。

| 状态轴 | 说明 | 典型状态 |
| --- | --- | --- |
| `parse_status` | 源文档是否解析完成、覆盖是否完整、结构是否存在待确认内容 | 解析中、已完成、部分解析、待确认、解析失败 |
| `unit_count_status` | 当前文档被组织成几个录入单元 | `single_default`、`multiple_confirmed`、`multiple_candidate`；用户覆盖结果另存为`user_override` |
| `audio_status` | 整份文档的音频批次状态 | 生成中、待整批验收、已验收、生成失败 |
| `audio_gate_status` | 必需音频产物是否满足技术交付条件 | `pending`、`passed`、`failed` |
| `audio_acceptance_status` | 用户是否验收了当前版本的整批音频 | `pending`、`accepted`、`invalidated` |
| `input_status` | 外部系统录入运行状态 | 未启用、待配置、待执行、执行中、已完成、失败可重试、结果待确认 |

`input_type_status`和`paper_category_status`属于配置识别状态，不作为顶部进度轴；只有处于`conflict`、`suggested`或`待确认`时，才在配置中心和交付中心摘要中提示。`parse_coverage_status`作为`parse_status`的明细保存，不能用“解析完成”掩盖仍有未归类内容。

服务端仍以`WorkflowSnapshot`中的结果、执行、控制、清理和总体状态，以及`state_version`、`draft_revision`、`current_step_id`为事实源；工作区条目的`requires_reconcile`、产物的`lifecycle_state/verified`和服务端返回的`available_actions`共同决定界面能否执行动作。Renderer只负责展示这些投影，不能根据本地按钮状态自行推断“可以重试”或“已经完成”。外部副作用未知时，必须进入对账或结果待确认状态，不能直接再次提交。

`audio_status=已生成`不等于“可录入”。只有`audio_gate_status=passed`且`audio_acceptance_status=accepted`时，音频才满足外部录入前置条件；前者检查所有必需产物是否`READY + verified=true`且格式事实一致，后者记录用户是否确认当前音频版本，两者缺一不可。

单元级录入状态与文档级汇总状态同时保存。文档包含多个录入单元时，汇总状态按实际结果计算：

- 全部未启动：`待开始自动化录入`
- 全部成功：`录入完成`
- 至少一个成功、至少一个失败：`部分完成`，必须同时显示成功/失败数量；“部分失败”只作为失败数量提示，不再作为另一种总状态
- 至少一个结果未知：`录入结果待确认`，优先处理对账，不允许直接重复提交
- 全部失败且确认无外部副作用：`录入失败，可安全重试`

“当前运行”只描述此刻正在执行的动作，“当前状态”描述等待或结果，不让两者互相替代。例如：

```text
当前运行：系统录入（第2/2个录入单元）
当前状态：1个已完成，1个录入结果待确认
音频交付：已完成
```

顶部流程仍只高亮第5步`音频交付中心`；交付中心内部使用一条轻量子流程或状态带表达当前子阶段：`音频产物核验 → 整批音频验收 → 配置复核 → 系统录入 → 结果对账/最终交付`。子阶段只作为第5步的上下文，不新增顶部节点；主区域只保留一个当前需要用户处理的主动作，其余状态和运行日志收进详情。

每个录入单元结果卡片必须固定展示以下信息：

```text
录入 ID：IN-xxxxxxxx
文档名称：模仿朗读-7上-U5-U6.docx
录入单元：U5 · 外网 · 第1稿
录入状态：已完成 / 失败可重试 / 结果待确认
审阅文档名：外研版七年级上册-U5（可复制到平台搜索）
```

审阅信息兼容保留在`review_url`及其状态字段中，例如`pending`、`available`、`unavailable`、`expired`。当前录入平台完成后使用`review_url_status=unavailable`和`review_url_source=platform_not_supported`，UI 改为展示 `document_name` 并提供逐项/批量复制；这不是录入失败，也不阻塞音频下载或录入结果保存。未来平台支持链接时，再按单元或运行范围异步回填对应 URL。

界面需要同时展示音频交付状态和系统录入状态，并始终告诉用户当前正在运行什么：

- `当前运行：音频生成`
- `当前运行：系统录入`
- `当前状态：待整批音频验收`
- `当前状态：录入失败，可安全重试`
- `音频交付：已完成`
- `系统录入：未启用（可继续录入）`

当一个文档包含多个录入单元时，系统录入状态区域还要显示单元数量和单元级进度，例如：

```text
系统录入（6个录入单元）
U5 · 外网 · 第1稿 · 待开始
U5 · 外网 · 第2稿 · 待开始
U5 · 教材 · 第1稿 · 待开始
U6 · 外网 · 第1稿 · 待开始
U6 · 外网 · 第2稿 · 待开始
U6 · 教材 · 第1稿 · 待开始
```

音频结果列表也必须按录入单元组织，而不是继续把所有内容平铺后只按题型分组：

```text
Unit 1 / U1
├─ Understanding Idea
│  ├─ 句子跟读
│  │  └─ 内容条目 → 音频片段
│  ├─ 段落跟读
│  │  └─ Conversation 1 → 多个音频片段
│  └─ 语篇跟读
│     └─ 语篇1 → 多个内容片段或一个合成音频
└─ Reading for writing
   ├─ 句子跟读
   │  └─ 内容条目 → 音频片段
   └─ 语篇跟读
      └─ 内容条目 → 多个自然段片段

Unit 2 / U2
└─ ……
```

每张音频卡片至少展示或保留以下对应关系：

- 所属录入单元及单元顺序
- 完整结构路径，例如`Section A / 段落跟读 / Conversation 1`
- 内容类型，例如`句子跟读`、`段落跟读`或`语篇跟读`
- 内容条目、内容片段顺序、说话人（如有）、来源定位和`content_item_id`
- `segment_id`及对应的`audio_artifact_id`

默认浏览路径是`按单元查看`，题型只作为单元内的二级分组和筛选条件；不再提供只有题型维度的主列表。搜索、按题型筛选和按单元筛选可以同时保留，但筛选后不能丢失条目的单元和原文上下文。

当音频来自`Conversation`或多段语篇时，卡片标题显示最小音频片段，卡片副标题显示完整父级路径。点击“查看对应原文”时，既定位到当前片段，也展开该片段所属的整段对话或语篇上下文，避免用户只看到一句而无法判断它属于哪一组内容。

如果现有服务端`available_actions`明确提供 ZIP 交付，目录或文件名应优先保留单元层级，例如`U1/Understanding Idea/句子跟读-001.mp3`；ZIP 不作为本次新增的必做能力，也不改变整批音频验收和整块重跑规则。

音频状态和系统录入状态相互独立，但音频验收按整批进行，系统录入按单元执行：

- 系统录入失败时，已经生成的音频仍可以试听和下载
- 外部系统录入失败且确认未产生外部副作用时，可以重试系统录入，不需要重新生成音频
- 外部提交结果未知时，先查询或对账，不得直接重复提交
- 任意一条音频不符合要求时，必须新建任务重新跑整块流程
- `audio_revision`、必需产物清单或音频清单摘要发生变化时，`audio_acceptance_status`立即变为`invalidated`，之前的整批音频验收状态需要重新确认；只修改不影响音频内容的系统录入配置不清除音频验收
- 多个录入单元由一次用户操作启动，但分别记录成功、失败和待确认状态

当系统录入状态为`未启用`时，交付中心必须保留`继续录入系统`按钮。该按钮不会重新生成音频；如果用户尚未完成音频验收，点击后先引导完成整批验收，再进入系统录入配置。

系统录入配置在交付中心默认以摘要展示。用户点击`编辑配置`后才重新打开配置抽屉；用户点击`确认配置并开始录入`后，才进入自动化录入。对于此前选择`只生成音频`、尚未保存系统录入配置的任务，`继续录入系统`可以直接打开同一抽屉的编辑态，并在保存后回到只读摘要。

### 12.2 交付中心动作矩阵

交付中心的主按钮根据“类型能力、单元边界、配置、产物、验收、平台会话和服务端动作”共同计算，不以一个前端状态字段决定：

| 条件 | 主动作 | 处理规则 |
| --- | --- | --- |
| 系统录入未启用 | `继续录入系统` | 保留音频交付能力；如果尚未验收，先引导完成整批验收 |
| 已启用但配置不完整 | `打开系统录入配置` | 打开配置抽屉，补齐缺失字段；不生成新音频 |
| 音频未通过技术闸门或用户验收 | `先完成音频验收` | 显示缺失产物、核验失败或未确认原因；不能开始外部录入 |
| `multiple_candidate`或用户尚未确认边界 | `确认录入单元` | 允许继续核对、配置和生成音频；外部录入前必须确认单元集合 |
| 前置条件全部满足且服务端允许执行 | `确认配置并开始录入` | 创建一次录入运行，按单元提交并保存目标快照 |
| 系统录入执行中 | `查看进度/日志` | 不重复创建运行；显示当前单元和整体进度 |
| 已成功完成 | `查看录入结果`、`下载音频` | 展示外部 ID、可搜索/可复制的审阅文档名和音频交付物；平台提供链接时再显示链接 |
| 结果待确认或外部状态未知 | `查询/对账` | 先确认外部记录状态，禁止直接重复提交 |
| 当前录入类型暂不支持外部录入 | 不提供启动动作 | 清楚说明“本版本仅支持解析、核对和音频交付”，不伪造成功状态 |

如果是已确认无外部副作用的失败，且服务端`available_actions`返回安全重试动作，才显示`安全重试系统录入`；未知状态、已提交未回执和已成功状态都不能显示直接重试。

### 12.3 最终交付

最终交付继续复用现有音频交付中心，不新增顶部流程节点。只生成音频的任务在通过音频技术产物闸门和整批用户验收后，显示“音频交付完成（系统录入未启用）”；选择系统录入的任务，只有在音频闸门通过且所有已启用录入单元的外部结果都已明确时，才显示“全部完成”。最终交付至少包括：

- 现有服务端允许的音频试听、下载或批量交付物，以及对应的音频批次和配置版本；ZIP只有在服务端动作明确允许时才展示
- 按录入单元展示的结果清单：`entry_id`、文档名称、单元名称、`external_record_id`、外部状态、失败原因
- 每个单元的可搜索审阅文档名和复制入口；平台支持时再展示单元级`review_url`或明确标注来源和范围的`run_review_url`
- 录入运行 ID、结构修订、目标快照和可查看的执行日志

存在部分成功、失败或未知结果时，页面可以交付已经生成的音频和已成功的单元，但总状态必须显示为“部分完成”或“录入结果待确认”，不能显示为“全部交付完成”。

### 12.4 关键异常提示

| 场景 | 用户提示 | 可执行动作 |
| --- | --- | --- |
| 音频产物缺失或未验证 | `还有 N 个音频产物未通过交付核验，暂不能录入系统` | 查看缺失产物、按服务端动作安全重试技术生成 |
| 整批音频尚未验收或验收已失效 | `请先验收当前版本的整批音频` | 返回音频列表试听并重新确认 |
| 解析有未归类内容 | `发现 N 段内容尚未归类，请先确认是否纳入本次录入` | 打开文稿核对，归类、移出或保留为待处理 |
| 平台模板不可用 | `当前平台录入模板已失效或无权访问` | 重新选择可用模板；不能继续提交 |
| 外部结果未知 | `外部平台结果暂时无法确认，请先对账` | 查询/对账；不提供直接重复提交 |
| 课文或词汇尝试外部录入 | `本版本支持解析、核对和音频交付，暂不执行该类型的系统录入` | 返回音频交付或继续编辑配置 |

## 13. 外部平台录入执行

视频中展示的外部平台录入操作不拆成新的顶部流程，而是封装为音频交付中心内部的一次系统录入运行：

```text
准备各录入单元参数 → 选择或匹配平台录入模板 → 创建或提交各单元平台任务 → 执行系统录入 → 获取各单元结果
```

外部平台提供的是一套完整的试卷或录入模板，本文统一称为`平台录入模板`，不拆成每条题目独立选择的模板。一套平台录入模板对应一个完整的录入单元；多个题型相同的录入单元默认批量复用同一套平台录入模板，不要求用户逐个重复选择。平台录入模板负责播放次数、播放间隔、准备时间、录音时间等规则，应用只负责选择或匹配模板，不重复配置这些规则。

系统录入必须满足以下前置条件：

- 所有必需音频产物通过技术产物闸门：具备`item_id`、`artifact_type=tts-segment`，满足`READY + verified=true`且格式事实一致
- 当前音频清单与`audio_revision`、`artifact_manifest_hash`一致
- 用户已经完成当前版本的整批音频验收
- 每个录入单元的系统录入配置完整
- 用户明确点击`确认配置并开始录入`

启动前还要检查：

- `unit_count_status`不能仍为`multiple_candidate`；如果用户尚未确认边界，只允许继续核对、配置和音频交付
- `input_type_status`和试卷场景的`paper_category_status`不能仍为`conflict`或仅有未确认建议；用户最终选择必须已经写入当前配置
- `parse_coverage_status`必须为`complete`；`partial`或`unclassified`时，未完成映射的内容必须先在文稿核对中处理，或由用户明确移出本次录入目标并重新计算覆盖状态，同时保留用户操作记录
- 每个录入单元都已经绑定一个可用的`platform_template_id`
- 平台登录会话、账号权限和模板版本有效
- 同一`entry_id`不存在仍在执行的外部操作、租约或未解决的活动运行
- 当前录入类型属于第一版允许执行外部系统录入的范围；课文和词汇在本版本只保留配置容器，不启动真实外部录入
- 服务端`available_actions`明确返回允许启动的动作，且`state_version`、`draft_revision`和当前配置版本没有过期

真正调用外部平台前，必须先持久化本次录入意图、`payload_hash`、`mapping_version`、单元目标快照、音频产物清单、配置版本和幂等键，再获取同一录入记录的执行租约。外部调用超时、会话中断或返回无法判断时，保存为`AMBIGUOUS`/`requires_reconcile`并进入查询或对账，不得因为没有收到回执就直接再次提交。

系统录入意图首次确认并保存时，为每个录入单元幂等创建唯一的`entry_id`，并写入平台文档名称、单元名称、当前配置版本、平台录入模板 ID和音频批次 ID；源文件名仍保留在工作区快照中，真正执行前再次校验这些快照没有过期。单套文档创建一个录入 ID；多套文档按每个录入单元分别创建录入 ID。这个 ID在执行、重试、结果展示和审阅文档名复制过程中保持不变。

启动后，应用按录入单元分别执行，但用户不需要逐个启动。单元之间共享当前音频批次和已经确认的公共配置；平台任务、执行进度和结果分别保留单元标识。

一次用户点击`确认配置并开始录入`只创建一个`input_run_id`，该运行下的每个单元分别关联自己的`external_operation_id`。某个单元的安全重试沿用原`entry_id`和`input_run_id`，只新增`attempt_id`；用户在配置或结构发生新版本后重新发起录入，则创建新的`input_run_id`。

每个单元的结果至少回写：`entry_id`、`document_name`、`unit_id`、`input_run_id`、`attempt_id`、`external_record_mapping_id`、`external_record_id`、`input_status`、外部记录状态、失败原因、`requires_reconcile`和审阅信息状态。当前平台写入平台文档名称，并将 `review_url` 置空、状态标为 `unavailable`；未来平台返回单元级审阅地址时才写入`review_url`，只能拿到整次运行地址时才写入`run_review_url`。不能因为当前没有链接而重复提交或阻塞其他结果。外部记录状态和平台操作状态分别保存，不能用“录入完成”覆盖`AMBIGUOUS`、未确认或对账中的结果。

单套和多套统一使用同一个录入记录结构；区别只在于当前任务包含的记录数量：

```json
{
  "entry_id": "IN-xxxxxxxx",
  "document_name": "外研版七年级上册-U5",
  "unit_id": "unit-001",
  "unit_label": "U5",
  "input_run_id": "run-xxxxxxxx",
  "attempt_id": "attempt-001",
  "external_record_mapping_id": null,
  "external_record_id": null,
  "input_status": "pending_execute",
  "external_status": "PENDING",
  "requires_reconcile": false,
  "review_url": null,
  "review_url_status": "unavailable",
  "review_url_source": "platform_not_supported",
  "run_review_url": null
}
```

单套任务保存一条记录，多套任务保存多条记录；`document_name`保存各自提交到平台的可搜索名称，`entry_id`、`unit_id`、单元名称和平台返回的`external_record_id`必须分别保存。

外部任务的重试必须遵循平台结果状态和服务端允许动作：

- 已确认未提交：允许安全重试
- 已提交但结果未返回：先查询或对账
- 已确认成功：不允许重复提交
- 状态未知：进入`录入结果待确认`，不能自动重提

如果某个录入单元的外部提交失败，只有在确认没有产生外部副作用时才允许重试该单元；这只是系统录入运行的错误处理，不改变“音频质量问题必须新建任务整批重跑”的规则。

课文和词汇的外部系统录入字段仍按当前版本范围执行：课文本版本只完善单元化解析、核对和音频映射，暂不因为增加录入单元层级而虚构尚未确定的课文专属录入字段。未来接入后，课文 Unit 可以直接复用同一套“按单元执行”的运行模型。

## 14. 兼容策略

不强制用户修改所有历史文档的文件名。

对于普通文件名，系统继续使用以下信息进行识别：

- 文件扩展名
- 文件名关键词
- 文档正文
- 文档结构
- 解析出的题型
- 用户已保存模板

新命名规则只作为提高识别率的辅助方式，不作为上传门槛。识别不到的字段留空或提示确认，不阻止用户进入后续配置。

对于一个文档包含多个专项试卷的情况，系统先按完整题型结构和内容块生成候选分组，再使用单元标记进行校验和命名。明确的`U1/U2`、`第1套`等文本不能单独触发拆分；只有当它们与独立的完整结构范围一致时，才作为增强证据。仍无法判断时按一个录入单元处理，并允许用户在文稿核对中拆分或合并。

课文文档的 Word 标题样式只能作为辅助信号。当前样例既有`Heading`样式，也有全部使用普通文本段落的文件，因此必须同时识别正文中的`Unit/U/第X单元`、`Section`、`Understanding Idea`等文本标记和题型结构，但文本标记只用于候选结构的命名、定位和校验，不能单独决定单元边界。

### 14.1 通用解析流水线

为了让试卷、课文和词汇共用同一套结构模型，解析不直接从段落生成最终音频条目，而分为六个阶段：

1. **保留源文档块**：按段落、表格、编号、换行和原始位置读取内容，保留原文、样式、来源位置和相邻关系。
2. **提取结构签名**：先识别题型/内容类型、说明、材料形态、编号和正文范围，比较连续结构是否重复；这一阶段不把`U1/U2`、`Section`或`Conversation`关键词直接当作录入单元边界。
3. **先判定单套或多套**：根据完整结构签名和独立内容范围生成`single_default`、`multiple_confirmed`或`multiple_candidate`，确定候选单元的数量和边界；用户确认结果另存为覆盖状态。
4. **构建解析树**：在边界确定后，用单元内的`Unit/U`等标记补充名称，用`Section`、题型、`Conversation`和主题标题建立父子关系，生成`录入单元 → 结构节点 → 内容条目 → 内容片段`；同名节点也必须保留各自的父节点和顺序。
5. **生成音频投影并验收**：在不改变解析树的前提下，根据音频规则生成一个或多个音频产物，为每个产物保留完整路径、条目 ID、片段 ID和源文档定位；生成后先通过技术产物闸门，再等待用户整批验收。
6. **生成工作区和外部目标投影**：将同一棵解析树映射到现有工作区条目、`artifact_id`、外部记录目标和录入运行；保存结构修订、目标快照和配置版本，不在转换时重新生成另一套按题型平铺的 ID。

解析器不要把“看到标题”简单等同于“新建录入单元”。完成单套/多套判断后，`U1/U2`等标记可以为已经确定的单元提供名称和定位，但不能单独创建边界；`Section A`、`Section B`、`Reading Plus`和`Conversation 1`默认都是已有 Unit 内的结构节点。题型标题也不能覆盖父级章节，必须作为树中的一层继续保存。

建议将解析结果以“结构树 + 平面索引”同时保存：结构树用于大纲、全文核对和上下文展示，平面索引用于检索、批量生成和音频状态更新。两者引用同一个`node_id`、`content_item_id`、`segment_id`和`audio_artifact_id`，不允许在工作区转换时重新按题型生成一套不完整的列表。

解析结果到现有领域模型的映射必须显式记录，不能让前端、解析器和录入脚本各自生成同义 ID：

| 方案层对象 | 现有系统锚点 | 映射要求 |
| --- | --- | --- |
| 录入单元 | 工作流元数据、外部记录目标中的`CONTENT_UNIT`（如当前目标模型支持） | 一个`unit_id`对应一个稳定的录入单元；`entry_id`作为面向业务的录入记录键 |
| 内容条目 | 现有工作区`item_id`或其明确的内容目标 | 一对一时直接关联；一对多时保存映射表和顺序，不能隐式拼接 |
| 内容片段 | 结构化目标或条目下的稳定片段元数据 | 保存`segment_id`、顺序、正文范围和目标快照，用于音频和原文定位 |
| 音频产物 | 现有`artifact_id` | 只引用已登记的工作区产物，受`lifecycle_state`和`verified`闸门约束 |
| 外部记录 | `external_record_mapping_id`、`external_record_id` | 映射、平台记录和本地业务键分开保存，不能用平台 ID替代本地血缘 |
| 外部运行 | `external_operation_id`、`attempt_id`、`input_run_id` | 一次提交意图、一次执行尝试和一次用户可见运行保持可追溯 |
| 结构/配置版本 | `draft_revision`、`target_revision_id`、配置版本 | 与`state_version`分开处理；并发冲突由服务端版本检查解决 |

分值、参考答案和音频—题目绑定关系从文档解析或既有系统关联结果读取，作为只读事实进入目标快照；它们不是系统录入配置字段，也不能在配置模板中重复维护。

### 14.2 对现有模块的影响

这次调整不改变顶部五步和已有音频生成入口，主要是把现有“按文档类型/题型平铺”的中间数据升级为结构树投影：

- **文档解析**：继续兼容现有的`doc_type`、`category`、`type_path`和`section`字段，同时新增单元、父子节点、内容条目和片段的稳定 ID；旧字段作为显示或兼容字段，不能再作为唯一层级来源
- **工作区与内容核对**：转换数据时保留从录入单元到当前节点的完整祖先路径，左侧大纲从解析树构建，不再只根据题型重新分组
- **音频生成**：每个音频任务引用`content_item_id`和`segment_id`，批量生成可以跨结构节点合并请求，但生成结果回写时必须恢复原结构路径
- **音频交付**：继续复用现有播放器和下载能力，列表改为单元优先、结构节点可展开；“查看对应原文”通过条目和片段 ID回到全文位置
- **系统录入**：仍按录入单元提交，录入内容从同一棵树读取，确保平台收到的题目顺序和音频绑定与核对页一致
- **历史解析结果**：没有新字段的旧结果统一包装成“一个默认录入单元 + 既有题型节点 + 内容条目”，不要求重新上传；新文档使用完整结构树

这样可以把本次结构升级控制在解析结果、核对展示、音频投影和系统录入映射四个连接点内，不额外增加顶部流程，也不破坏已有的音频配置和生成任务。

## 15. 最终产品原则

1. 音频生成是主流程，系统录入是可选分支。
2. 系统录入配置优先在配置中心完成；音频交付中心默认只做最终展示、修改和确认，但用户也可以在此前选择“只生成音频”后，从交付中心后置开启并完成系统录入配置。
3. 用户先看到并完成整批音频验收，再执行系统录入。
4. 不增加新的顶部流程节点，最大化复用现有交付中心。
5. 自动识别先判断结构和单套/多套，再用关键词补充名称与层级；自动识别尽力而为，但不强行猜测。
6. 识别结果可以被用户随时修改，用户选择永远优先。
7. 试卷、课文、词汇三种录入类型都可手动切换，不做禁用限制。
8. 文档负责提供题目、分值、答案和绑定关系，平台录入模板负责录音规则；应用配置模板只负责复用本应用配置。
9. 省市区、学段、年级使用标准字典和 ID 提交。
10. 用户保存的模板按试卷、课文、词汇固定分类，选择类型后只展示对应模板。
11. 音频质量问题必须新建任务整块重跑；外部系统录入失败则按安全状态独立处理。
12. 所有录入类型都遵循“源文档 → 音频批次 → 录入单元 → 可嵌套结构节点 → 内容条目 → 内容片段 → 音频”的层级；音频批次可以覆盖整份源文档，核对、音频结果和系统录入按录入单元分别组织和执行，一个文档可以对应多个专项试卷、多个课文 Unit或未来多个词汇单元。
13. `Unit`、`Section`、`Conversation`、语篇小标题和题型只是结构树中不同角色的节点，不用固定层数或单一`category`字段限制解析；父子关系、顺序、原文定位和置信度必须完整保留。
14. 技术产物状态、用户整批验收和外部录入结果分别判断；`READY + verified`、用户确认和外部成功不能互相替代。
15. 现有`WorkflowSnapshot`、工作区条目、产物事实、`available_actions`和外部操作状态是实现事实源，方案中的显示状态只是投影。
16. 每个录入单元都必须能追溯到录入 ID、可搜索文档名称、结构/配置版本、音频产物、外部记录和审阅信息状态；未知结果必须对账，不能当作完成。
17. 自动匹配模板只补全缺失字段；用户明确应用模板并确认冲突后，确认结果才成为最高优先级的当前配置。
18. 一次用户启动对应一个`input_run_id`，每个录入单元使用自己的`entry_id`和外部操作记录，重试只增加`attempt_id`。
19. 第一版只承诺现有服务端已提供的音频交付动作；ZIP、课文外部录入和词汇外部录入都不能被方案文字提前承诺为已支持能力。

| 结果交付 | 单套和多套均按录入单元展示`entry_id`、平台文档名称、`external_record_id`、状态和复制入口；当前平台无链接时明确标记不可用但不报错，部分或未知结果不显示为全部完成；ZIP只有服务端动作明确提供时才展示 |
