# 外部音频容错匹配

本地 SenseVoice 识别完成后，整段录音由 `workflow/audio_asr.py` 对齐到文档
题目，分音频导入由 `workflow/audio_text_matching.py` 比较识别文字和原文。
识别模型和原始转写不变，界面仍显示模型实际输出；归一化只用于计算相似度。

## 整段录音：结构优先的对齐（v2）

匹配不再只靠“逐窗口文本相似度”，而是先建立录音的结构骨架，再用文本补齐：

1. **题号锚点**：录音里每道听力题前都会读题号（one/two/…/ten，识别可能
   写成 `ten0,`、`thre,` 这类噪声形式）。`workflow/audio_structure.py`
   解析出题号后，把题号后面那段语音直接归给同号题目——即使 ASR 把题干
   文字听错，只要该题号后的音频位置能确认，就不再整题漏掉；完全识别失败
   或空转写等无法确认位置的仍按缺失处理，避免绑错音频。
2. **中文指令/旁白**：`听第N段对话，回答第X~Y个问题`、
   `请根据所听内容回答第7~10四个问题` 这类指令解析出题号范围；`开始录音`
   `停止录音` 等旁白用于确认一句话真正结束。题号提示行和旁白不会进入
   切割片段；题号提示必须与题干之间有停顿，ASR 把句首数词（如
   `One night…` 的 `One`）单独切出时按正文处理。
3. **文本匹配补齐**：长文、对话、中文引导语没有题号，仍按文本相似度匹配；
   题号命中会给同号题目加分，题号不符会降权，避免相似题干互相抢占。
4. **缺题回退**：文本匹配没命中、但录音里存在该题题号的，按题号后的
   语音位置切出片段并给出候选置信度：文字也基本对得上时自动绑定；文字
   太差时保留片段、列为“需要确认”，用户手动选择即可，不再只显示
   “缺少音频”。

`tools/audio_match_eval.py` 用真题 fixture 量化匹配效果（题目召回、缺失、
切割起止误差、跨题重叠），当前 2025 深圳第 1 套 16/16、2024 深圳第 2 套
19/19，切割误差 ≤0.01s。

## 文本归一化与容错

匹配先统一大小写、标点、空格、常见英文缩写与数字写法。例如 `don't` 和
`do not`、`Mr` 和 `mister`、`7:00 AM` 和 `seven AM`、`六十` 和 `60`
可以用相同的形式比较。

字符比较采用 RapidFuzz 的 Levenshtein 最优编辑对齐，允许少量错字、漏字、
多字。含中文时增加拼音比较通道，处理 `Yangshuo`、`阳朔` 和混写的
`杨ang朔`；读音匹配有折扣，相同拼写优先。拼音由本地字典转换，不下载
新的识别模型。依赖为 `rapidfuzz` 和 `pypinyin`，发布包同时收集其运行文件。

面积写法 `160 km2`（上标 2 被归一化成普通数字）按朗读时的
`160 square kilometers` 比较，单位里的 2 不计入数字校验。

数字、否定词和英文疑问词单独检查。`15` 与 `60`、`can` 与 `cannot`、
`how` 与 `why` 的变化不能按普通错字自动接纳。候选题目过于接近时仍需
人工确认。相似度是文字匹配分数，不是语音识别准确率。

短题（原文不超过 80 个字符，通常是题干或中文引导语）如果紧跟考试旁白
（开始录音／停止录音等）结束，就以旁白作为这句话真正结束的证据：识别把
结尾一个词听错时仍算完整，不会漏掉整题。超过 80 个字符的长短文不享受
这条放宽；识别失败的片段也不会被当作旁白。

整段录音同时检查全文覆盖与开头、结尾的对齐证据，缺失的结束句不能通过
较长的正确开头补足。已经识别为完整文件的结果也必须检查全文；只识别了
开头的分音频允许与原文前缀比较。同一语音范围只分配一次，两遍朗读保持
各自边界后合并，不跨读次或跨题抢占片段。

## 回归覆盖

回归覆盖中英混写地名、中文同音字、拼写误差、缩写、数字写法、歧义候选、
关键内容变化、截断内容、题号噪声（`ten0`/`thre`）、中文指令题号范围、
ASR 听错题干时按题号回退，以及真实试卷识别记录的题目和切割范围。
